// HOW PROVABLY FAIR AVIATOR WORKS
01
SERVER COMMITS TO A SEED
Before the round starts, the casino generates a random serverSeed and publishes its SHA-256 hash. This "commits" them to the result — they can't change it after you bet.
02
CLIENT SEED IS COMBINED
Your browser generates a clientSeed. The crash point is derived from HMAC-SHA256(serverSeed, clientSeed + ":" + nonce). The nonce is the round number — it increments each round so each result is unique.
03
CRASH POINT IS CALCULATED
The first 8 hex characters of the HMAC hash are converted to a number. The crash point formula is:
crashPoint = max(1.0, (2^32 / (h + 1)) * (1 - houseEdge))
where h is the hex value and houseEdge is typically 1% (0.01).
04
AFTER THE ROUND — VERIFY IT
After the round ends, the server reveals the original serverSeed. You can now run the same calculation yourself. If the result matches the claimed crash point — the round was fair. If not — the site is rigged.
05
HOW RIGGED SITES GET CAUGHT
A rigged site either: (1) never reveals the server seed, (2) reveals a seed that doesn't match the committed hash, or (3) shows a crash point that doesn't match the calculation. All three are detectable with this tool. Pattern analysis can also detect if crash distribution is statistically abnormal — crashing too early too often is a statistical fingerprint of a rigged RNG.
// SIGNS A SITE IS RIGGED
✗ No "Provably Fair" button shown after rounds
✗ Server seed hash not shown before the round
✗ Revealed server seed doesn't match pre-committed hash
✗ Calculated crash point doesn't match what was shown
✗ Crash distribution shows too many sub-2x results (>60%)
✗ Long streaks of sub-2x crashes that defy probability
✗ House edge calculated from history is above 5%
