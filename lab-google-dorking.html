WHAT IS GOOGLE DORKING?
▼

Google Dorking (also called Google Hacking) is the art of using advanced Google search operators to find information that is not meant to be public.

Google indexes billions of web pages — including files, directories, login pages, and config files that were accidentally exposed. Dorking lets you find them using specific search syntax.

WHY IT MATTERS

Security researchers and bug bounty hunters use Google Dorks every day to:

  • Find exposed admin panels and login pages
  • Discover sensitive files like .env, .config, passwords.txt
  • Locate open directory listings
  • Find vulnerable software versions
  • Map the attack surface of a target
⚠ LEGAL NOTE
Google Dorking itself is legal — you are only using Google's search engine. However, accessing files you find without permission is illegal. In this lab everything is sandboxed and safe.
2
THE CORE OPERATORS
▼

These are the building blocks of every Google Dork. Learn these and you can build powerful searches.

site:

Limits results to one specific domain.

site:example.com

inurl:

Searches for a keyword inside the URL of a page.

inurl:admin
inurl:login
inurl:dashboard

intitle:

Searches for a keyword inside the page title.

intitle:"index of"
intitle:"admin panel"

filetype:

Finds specific file types indexed by Google.

filetype:pdf
filetype:env
filetype:sql
filetype:log

intext:

Searches for specific text found inside a page's content.

intext:"password"
intext:"DB_PASSWORD"
3
COMBINING OPERATORS
▼

The real power of dorking comes from combining multiple operators in one search. This is how hunters find real vulnerabilities.

FIND ADMIN PAGES ON A SPECIFIC DOMAIN

site:example.com inurl:admin

FIND EXPOSED ENV FILES

site:example.com filetype:env

FIND OPEN DIRECTORIES

site:example.com intitle:"index of"

FIND EXPOSED PASSWORDS

site:example.com intext:"DB_PASSWORD" filetype:env

FIND LOGIN PAGES

site:example.com inurl:login intitle:"login"
💡 PRO TIP
Real hunters replace "example.com" with their bug bounty target domain. The more specific your dork, the more useful your results.

REAL WORLD EXAMPLES
▼

These dorks have been used in real bug bounty reports. Study them carefully.

FIND EXPOSED BACKUP FILES

site:target.com filetype:bak OR filetype:backup OR filetype:old

FIND PHPINFO PAGES (exposes server info)

site:target.com inurl:phpinfo.php

FIND WORDPRESS LOGIN PAGES

site:target.com inurl:wp-admin

FIND EXPOSED GIT REPOSITORIES

site:target.com inurl:.git

FIND ERROR MESSAGES WITH STACK TRACES

site:target.com intext:"Fatal error" OR intext:"stack trace"

5
HOW TO BUILD YOUR OWN DORKS
▼

Once you understand the operators, you can build custom dorks for any target. Here is the method:

STEP 1 — IDENTIFY YOUR GOAL

What are you looking for? Admin panel? Config files? Login pages? Define your target first.

STEP 2 — CHOOSE YOUR OPERATORS

Pick operators that match your goal. Combine site: with inurl: or filetype: for precision.

STEP 3 — TEST AND REFINE

Run the dork. If you get too many results, add more operators to narrow it down. If you get zero, broaden your search.

STEP 4 — DOCUMENT EVERYTHING

Screenshot every finding. Note the exact URL, what was exposed, and when you found it. This becomes your bug bounty report.

🎯 PRACTICE DORK
Try this on any bug bounty target:

site:target.com ext:php inurl:id=

This finds PHP pages with an ID parameter — a classic starting point for IDOR and SQLi testing.
